# Future Store — متجر هواتف إلكتروني

متجر إلكتروني عربي (RTL) للهواتف الذكية، مبني بـ PHP و MySQL، مع واجهة برمجية (API) يستهلكها تطبيق Flutter للعملاء.

---

## المزايا

**للعميل**
- تصفّح الكتالوج، بحث، فلترة حسب الماركة والسعة والسعر، ترتيب، وترقيم صفحات
- صفحة منتج بمواصفات ونسخ (سعة/لون/سعر/مخزون) وتقييمات
- مقارنة حتى 4 أجهزة
- سلة وطلب بالدفع عند الاستلام
- متابعة الطلبات وحالتها، وطلب صيانة للأجهزة المُسلَّمة
- تقييم المنتجات **المشتراة والمستلَمة فقط**
- إشعار عند توفّر نسخة نفدت

**للموظف**
- لوحة بالطلبات المُسندة إليه فقط (توزيع بالتناوب)
- قبول/رفض الطلبات، تحديث الحالة، تأكيد تحصيل النقد
- متابعة طلبات الصيانة المُسندة إليه

**للمدير**
- كل ما سبق بلا قيود + إدارة المنتجات والماركات والمخزون
- إدارة المستخدمين (إنشاء موظفين، تعطيل، حذف، إعادة تعيين كلمة سر)
- تقارير: ملخص مالي، الأكثر مبيعًا، المخزون المنخفض، أفضل العملاء، أداء الفريق
- تصدير التقارير للطباعة/PDF

## المكدّس التقني

| الطبقة | التقنية |
|---|---|
| الخادم | PHP 8.2 (بلا أُطر عمل، بلا Composer) |
| قاعدة البيانات | MySQL / MariaDB 10.4 — 13 جدولًا InnoDB |
| الواجهة | HTML + CSS يدوي + JavaScript خام (RTL) |
| تطبيق الجوال | Flutter (مشروع منفصل) يستهلك `api/` |
| الوصول لقاعدة البيانات | PDO + prepared statements حقيقية |

**صفر تبعيات خارجية** — لا Composer ولا npm.

---

## المتطلبات

- PHP **8.2+** (يستخدم `match`, `never`, `str_ends_with`, named arguments)
- MySQL 5.7+ أو MariaDB 10.4+
- Apache مع `mod_rewrite` و `mod_headers` و **`AllowOverride All`** (ملفات `.htaccess` تحمل ضوابط أمنية أساسية)

## التنصيب

**1. انسخ المشروع** إلى جذر الخادم (مثل `htdocs/future_store`).

**2. أنشئ قاعدة البيانات والبنية:**
```sql
CREATE DATABASE future_store CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```
```
mysql -u root future_store < schema.sql
```

**3. أنشئ مستخدمًا محدود الصلاحيات** (لا تستخدم root):
```sql
CREATE USER 'fstore_user'@'localhost' IDENTIFIED BY 'ضع-كلمة-سر-قوية';
GRANT SELECT, INSERT, UPDATE, DELETE ON future_store.* TO 'fstore_user'@'localhost';
FLUSH PRIVILEGES;
```
> التطبيق لا ينفّذ أي أوامر بنية (CREATE/ALTER/DROP) وقت التشغيل، فهذه الصلاحيات الأربع تكفيه. أي ثغرة مستقبلية لا تستطيع حذف جدول ولا قراءة قواعد أخرى.

**4. أنشئ ملف الإعداد:**
```
copy includes\config.example.php includes\config.php
```
ثم عدّل `DB_USER` و`DB_PASS` بقيمك.

**5. افتح** `http://localhost/future_store/`

كل الإعدادات في `includes/config.php`:

| الثابت | الوصف |
|---|---|
| `DB_HOST` / `DB_NAME` / `DB_USER` / `DB_PASS` | اتصال قاعدة البيانات |
| `SITE_NAME` | اسم المتجر |
| `SHIPPING_FEE` | رسوم الشحن الثابتة |
| `CURRENCY` | رمز العملة |
| `SITE_EMAIL` / `SITE_PHONE` | بيانات التواصل في التذييل |
| `BASE_URL` | يُكتشف تلقائيًا — لا تعدّله |

## الحسابات

المستودع **لا يحتوي على أي حسابات أو كلمات سر**. `schema.sql` بنية فقط بلا بيانات.

أنشئ حساب المدير الأول يدويًا:
```sql
INSERT INTO users (role, full_name, email, password_hash)
VALUES ('admin', 'اسم المدير', 'admin@example.com', '<bcrypt-hash>');
```
لتوليد الهاش:
```
php -r "echo password_hash('كلمة-السر', PASSWORD_BCRYPT);"
```
ثم سجّل الدخول من `/staff/login.php`.

## نظرة على الـ API

القاعدة: `/api/` — المصادقة عبر `Authorization: Bearer <token>`.

| الطريقة | المسار | الوصف |
|---|---|---|
| POST | `register.php` | إنشاء حساب عميل ويعيد توكنًا |
| POST | `login.php` | تسجيل دخول عميل ويعيد توكنًا |
| POST | `logout.php` | إبطال التوكن الحالي |
| GET/PUT | `me.php` | عرض/تعديل بيانات الحساب |
| POST | `change-password.php` | تغيير كلمة السر ويعيد توكنًا جديدًا |
| GET | `home.php` | الماركات والأكثر مبيعًا |
| GET | `brands.php` | كل الماركات |
| GET | `products.php` | قائمة المنتجات (`q, brand, min, max, storage, sort, page, per_page`) |
| GET | `product.php` | تفاصيل منتج (`slug` أو `id`) |
| POST | `order-create.php` | إنشاء طلب |
| GET | `orders.php` | طلبات صاحب التوكن |
| GET | `order.php` | تفاصيل طلب (`id`) |

**ملاحظات مهمة:**
- **التطبيق للعملاء فقط** — الموظفون والمدراء لا يحصلون على توكن API بالتصميم.
- **Idempotency:** `order-create.php` يقبل رأس `Idempotency-Key`. وإن لم يُرسل، يُشتق مفتاح تلقائي من محتوى الطلب ضمن نافذة 5 دقائق — فالنقر المزدوج أو إعادة المحاولة بعد انقطاع الشبكة **لا ينشئ طلبًا مكررًا**.
- كل القوائم مُرقَّمة بحد أقصى 48 عنصرًا للصفحة.
- الأسعار والمجاميع تُحسب على الخادم دائمًا؛ أي سعر يرسله العميل يُتجاهل.

## ملاحظات أمنية

الضوابط المطبَّقة والمُختبَرة:

- **SQL Injection:** PDO prepared statements حصريًا · `ORDER BY` عبر allowlist · `LIMIT/OFFSET` بقيم مقيّدة
- **XSS:** كل الإخراج عبر `e()` (htmlspecialchars) · سياسة CSP
- **CSRF:** توكن على كل عملية تغيّر الحالة، وعلى تسجيل الخروج
- **التحكم بالوصول:** يُفرض على الخادم في كل مسار — العميل يرى طلباته فقط (`WHERE user_id = ?`)، والموظف الطلبات المُسندة إليه فقط
- **كلمات السر:** bcrypt · تغييرها يُبطل توكنات التطبيق وجلسات المتصفح الأخرى
- **الجلسات:** `session_regenerate_id` عند الدخول · HttpOnly · SameSite=Lax · Secure تلقائيًا على HTTPS
- **التخمين:** قفل 15 دقيقة بعد 5 محاولات على حساب أو 10 من نفس الجهاز
- **الرفع:** allowlist للامتدادات + فحص `getimagesize` + تعطيل تنفيذ السكربتات في مجلد الصور
- **آلة حالات الطلب:** الانتقالات مقيّدة (لا `delivered → pending`) · الدفع عند الاستلام لا يُسجَّل قبل التسليم · كل تغيير يُسجَّل في `order_events`
- **رؤوس الأمان:** CSP · X-Frame-Options · X-Content-Type-Options · Referrer-Policy · HSTS (على HTTPS)

**قبل النشر على الإنترنت:**
1. انقل بيانات قاعدة البيانات إلى متغيرات بيئة بدل `config.php`
2. فعّل HTTPS بشهادة صالحة
3. اضبط كلمة سر لحساب `root` في MySQL
4. فعّل نسخًا احتياطيًا مجدولًا
5. راجع `ThreadsPerChild` و`innodb_buffer_pool_size` لبيئة الإنتاج

## حدود معروفة

- **الدفع نقدًا عند الاستلام فقط** — لا توجد بوابة دفع إلكتروني.
- **لا يوجد نظام بريد إلكتروني** — طلب "أبلغني عند التوفر" يُسجَّل في قاعدة البيانات ويظهر للمدير، ولا يُرسل بريدًا.
- **لا يوجد مرتجعات/استرداد** كعملية منفصلة؛ الإلغاء والرفض متاحان فقط.
- **رسوم شحن ثابتة** لكل الطلبات (قابلة للضبط في `config.php`)، بلا مناطق شحن.
- **عملة واحدة** مُعرّفة في الإعداد.
- **الصيانة** بثلاث حالات (`new`, `in_progress`, `resolved`) بلا تكلفة إصلاح أو فني مُسند.
- **الضمان** يُحسب من `warranty_months` الحالي للمنتج، ولا يُلتقط كصورة تاريخية وقت البيع.
